# Reader text rendering and punctuation placement

## Source assets ➜ tokens
* Assets are loaded through `MorphDocumentParser.loadFromAssets`, which routes `.jsonl` to the JSONL reader and everything else to the FB2 parser. 【F:android-app/src/main/java/com/example/ttreader/util/MorphDocumentParser.java†L18-L34】
* The FB2 parser (`Fb2MorphParser`) walks `<style name="morph">` tags, capturing any text that precedes them as `prefix` and reading the token text from the `surface` attribute or inner text. Morphology and translations are attached from custom attributes before emitting a `Token` object. Closing punctuation tokens without their own morphology and without visible prefix text are merged into the previous morph token with a narrow NBSP/word‑joiner bridge so the punctuation lives inside the same `<style name="morph">` span. Paragraph boundaries flush any accumulated prefix as a synthetic whitespace token and append a newline token. 【F:android-app/src/main/java/com/example/ttreader/util/Fb2MorphParser.java†L31-L205】

## Tokens ➜ plain text and spans
* `ReaderView.buildContent` iterates the token list and gradually builds a `StringBuilder plain` plus a parallel `List<TokenSpan>` used for highlighting and pagination. 【F:android-app/src/main/java/com/example/ttreader/reader/ReaderView.java†L1738-L1857】
* For each token it normalizes inline whitespace in `prefix`, trims trailing spaces when the following surface is closing punctuation, and appends the prefix. If a closing mark follows, `bindClosingPunctuationToPreviousToken` converts any trailing breakable whitespace to a narrow NBSP or injects word‑joiner plus zero‑width NBSP so the upcoming punctuation sticks to the previous token. 【F:android-app/src/main/java/com/example/ttreader/reader/ReaderView.java†L1738-L1786】【F:android-app/src/main/java/com/example/ttreader/reader/ReaderView.java†L296-L332】
* The surface text is appended next. Leading spaces before closing punctuation are stripped so the punctuation token starts immediately after the joiner. For tokens with morphology, a `TokenSpan` records the character range and learning metadata; otherwise synthetic spans still mark the range so pagination can snap to punctuation and whitespace. After the loop, any uncovered tail text is wrapped in a synthetic span. 【F:android-app/src/main/java/com/example/ttreader/reader/ReaderView.java†L1786-L1847】
* Sentence ranges are computed from the finished string with `BreakIterator`, yielding `LoadResult(text, tokenSpans, sentenceRanges)` that drives pagination and highlighting. 【F:android-app/src/main/java/com/example/ttreader/reader/ReaderView.java†L1857-L1887】

## Pagination and layout
* When the view measures its viewport, `recomputePagination` slices the document into page ranges that fit the available width/height. It renders chunks through `StaticLayout` to find the last fully visible line, then trims trailing whitespace and snaps the break to the end of the last `TokenSpan` that fits. 【F:android-app/src/main/java/com/example/ttreader/reader/ReaderView.java†L964-L1040】
* `extendIndexThroughPunctuation` extends a candidate break through optional whitespace plus trailing punctuation characters (commas, quotes, dashes, brackets, etc.), so a break chosen at the end of a word is pushed past any immediately following marks. This keeps punctuation in the same page and often the same line. 【F:android-app/src/main/java/com/example/ttreader/reader/ReaderView.java†L1040-L1120】

## Page render
* `applyPage` materializes the requested slice into a `SpannableStringBuilder`, reattaches every `TokenSpan` that overlaps the window, and either renders immediately or defers until the view is laid out. `renderPage` then calls `setText`, kicking off Android's measure/layout/draw to position glyphs and punctuation according to the `StaticLayout` results. 【F:android-app/src/main/java/com/example/ttreader/reader/ReaderView.java†L1196-L1327】【F:android-app/src/main/java/com/example/ttreader/reader/ReaderView.java†L432-L557】

## How punctuation positions emerge
* FB2 exports often split punctuation into their own tokens with empty prefixes. The loader preserves that split, but `buildContent` injects joiners ahead of the mark and normalizes whitespace so the punctuation's character range immediately follows the preceding token's range. 【F:android-app/src/main/java/com/example/ttreader/reader/ReaderView.java†L1738-L1808】
* Because punctuation spans sit in `tokenSpans`, pagination respects them: `adjustPageEndToTokenBoundary` chooses the last span end that fits, and `extendPageEndThroughPunctuation` pushes further across any trailing marks. Combined, these steps decide both the page break and the line wrap positions that Android's layout engine will use when it lays out the `Spannable`. 【F:android-app/src/main/java/com/example/ttreader/reader/ReaderView.java†L997-L1112】
